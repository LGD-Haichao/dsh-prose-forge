# 文件交付

管的是“一份要交给别人读的文件”，不是聊天回复。区别在于：文件要能脱离对话独立成立，读者看不到你刚才问了什么。

## 定格式之前

先确认三件事，缺一件就问：

1. **落盘在哪** — 目录和文件名。用户没说就按内容起名，放在当前工作目录，并在交付时明确报出完整路径。
2. **给谁读** — 决定要不要解释背景知识。
3. **多长** — 用户没说就按信息量定，不要问“需要多少字”。

需要 .docx / .xlsx / .pptx / PDF 时，转交office系列skill处理格式与公式，不要自己拼OOXML或手写xlsx的xml。本skill只管内容与结构。

## 结构

- 开头第一段就是结论或结论表，不写“随着……的发展”。
- 章节数由信息量决定。三节够就别写五节。
- 每节首句说这节干什么，然后直接给内容。
- 层级不超过三层。三级标题还压不住，说明该拆成两个文件。
- 各节篇幅差异应当反映重要性。长度都差不多，通常是凑数。

## 标题

写名词或动宾短语：`怎么装插件`、`三个性能瓶颈`、`接口变更清单`、`为什么放弃 X`。

不写：`浅谈`、`浅析`、`探析`、`刍议`、`管窥`、`视域下`、`背景下`、`赋能`、`驱动`、`实践与思考`。

同一层级结构对齐：全是动宾，或全是名词，不混用。

## 表格与列表

- 表格只放并列或对比：同一组字段、多个对象。
- 单元格放短语，不放整句。放整句说明该用段落。
- 少于3行的“表格”改成句子。
- 列表项必须独立成立，不依赖上一条的语法。

## 引用与数据

- 每个数字带出处：版本号、命令、文档链接、实测环境。
- 没出处的判断写成判断（“我建议”“实测下来是这样”），不写成客观事实（“研究表明”）。
- 直接引用、转述、自己的推论，三者不混着写。

## 收尾

- 不写“综上所述”“总而言之”，结尾停在最后一条实质信息上。
- 需要的话最后给“下一步”或“还没做的事”，不给情绪。

## 交付时说明四件事

1. **路径** — 文件落在哪，用可点击的完整路径。
2. **做了什么** — 结构、篇幅、覆盖范围。
3. **没做什么** — 哪些没写、为什么没写。
4. **假设** — 用了什么前提，读者改哪里会影响结论。

## 自检

交付前调 `prose_check`，`mode=doc`。它会额外检查标题八股和空转表述（“本节将”“本文将从”）。

结构指标里最该看的是两个：`paraCV`（各段长度是否过于均匀）、`headingRatio`（标题是否过密）。这两个过了，词层面的小毛病不影响可读性。
