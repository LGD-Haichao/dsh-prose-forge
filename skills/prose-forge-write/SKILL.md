# 写长文

六步。材料不够就停在前一步，不要跳过它去堆字数。

## 1. 立意

先用一句话说清：这份东西写完之后，读者多知道什么，或者会去做什么。

写不出这一句就回到用户那里问，别开始写。这一句话不是标题，是你判断后面每一段该不该留的尺子。

## 2. 摸材料

清点手上有什么：代码、日志、文档、数据、别人的说法、用户给的原话。

- 材料够：直接进第 3 步。
- 缺可查的：去查，记下出处。
- 缺只有用户知道的：一次问，不超过三个问题。

不允许的替代方案：用形容词、背景铺垫、行业趋势把字数凑满。

## 3. 对齐语感

有样本就先读再动笔：用户以前写的文章、指定作者的语料、用户给的范文。

读的时候看六层，不要只总结成“风格简洁”这种废话：

1. 句子怎么起头（主语先行，还是状语先行）
2. 句子怎么收尾（停在事实，还是停在判断）
3. 用不用书面语（“其”“之”“该”出现的频率）
4. 怎么称呼对方（你 / 您 / 读者 / 不提）
5. 语气轻重（有没有反讽、自嘲、口气硬的断言）
6. 段落怎么切（一段一个意思，还是一段一个例子）

没有样本就用文风契约的默认文体，不要再问“您希望什么风格”。

## 4. 出骨架

给出每节的一句话主张，让用户确认结构再展开。

用户说“直接写”就跳过确认，但骨架仍要在心里成立：每节一句话，说不出来的节不要。

## 5. 展开

一节一节写。

写到某节发现没材料：回头改骨架，删掉这节或者合并到别的节，不要用形容词填。

每节的写法：首句交代这节干什么，然后直接给具体的东西（数字、命令、案例、代码、引文）。

## 6. 自检与交稿

交稿前调 `prose_check`，用自己的稿子当输入。

- 判定 `clean` 或 `基本干净`：可以交。
- 有 `模板腔` / `模板腔重`：逐条看命中明细，按 advice 改。
- 结构问题（句长过于均匀、各段长度相近）优先处理，这类比词更显眼。

需要改写清单时调 `prose_rules`，`part=direct` 是十条详解带改写示例，`part=slop` 是 AI 腔词表。

交稿时说明：改了几处、留了几处、为什么留。留的地方通常是引文、术语、用户坚持的表述。

## 不要做的事

- 不写“综上所述”收尾。
- 不为了对称把两件事拆成四节。
- 不在每节末尾都小结一遍。
- 不把能一句话说清的事拆成三条 bullet。
- 不编出处。没有就写“我推测”，或者不写。
